<objective>
Build the two-worker threading architecture: USB Worker (WebUSB device access, RTL-SDR control, IQ sample streaming), DSP Worker (ring buffer reader skeleton), SharedArrayBuffer ring buffer between them, and the worker bridge that wires everything to main-thread state.

Purpose: This is the core plumbing that all subsequent phases build on. The worker architecture cannot be retrofitted -- it must be established now. USB I/O and DSP processing must never touch the main thread.
Output: Working USB Worker with RTL-SDR device control, DSP Worker skeleton, ring buffer, and bridge connecting workers to reactive state.
</objective>

       ```typescript
       import { RingBuffer } from 'ringbuf.js';

       export function createRingBuffer(capacityBytes: number): {
         sab: SharedArrayBuffer;
         writer: RingBuffer;
       } {
         const sab = RingBuffer.getStorageForCapacity(capacityBytes, Uint8Array);
         const writer = new RingBuffer(sab, Uint8Array);
         return { sab, writer };
       }

       export function getRingBufferReader(sab: SharedArrayBuffer): RingBuffer {
         return new RingBuffer(sab, Uint8Array);
       }

       export function getRingBufferFillPercent(rb: RingBuffer): number {
         return (rb.available_read() / rb.capacity()) * 100;
       }
       ```
       Note: Check ringbuf.js API at import time. The `RingBuffer.getStorageForCapacity()` static method returns a SharedArrayBuffer. The constructor takes (sab, TypedArrayConstructor).     4. Create `src/lib/usb/usb-worker.ts` -- the USB Worker entry point:
       ```typescript
       /// <reference lib="webworker" />
       ```

       The worker handles these incoming messages (MainToUsbMessage):
       - `'connect'`: Call `RtlDevice.findAndConnect()`. On success, post `{ type: 'status', status: 'connected' }` and `{ type: 'device-info', name: '...' }`. On failure, post `{ type: 'status', status: 'error', error: 'Device not found' }` or `{ type: 'status', status: 'error', error: 'Connection failed' }`.
       - `'disconnect'`: Call `device.close()`. Post `{ type: 'status', status: 'disconnected' }`.
       - `'configure'`: Call `device.configure(frequency, gain, sampleRate)`. No response needed on success; on error post status error.
       - `'start-capture'`: Create SharedArrayBuffer ring buffer (4MB). Send the SharedArrayBuffer to DSP Worker via a MessagePort (the bridge will set up a MessageChannel and send one port to USB Worker, one to DSP Worker). Start an async capture loop: `while (capturing) { read 16384 bytes from device -> push to ring buffer -> track stats }`. Post stats to main thread every 500ms.
       - `'stop-capture'`: Set capturing flag to false. Loop exits. Post capture-stopped to DSP Worker.

       Listen for `navigator.usb` `disconnect` event: if the currently-connected device is unplugged, set capturing = false, post `{ type: 'status', status: 'disconnected' }`.

       The worker also receives a `'set-dsp-port'` message with a MessagePort for direct USB-to-DSP communication. Store this port for sending ring buffer SAB and capture state to DSP Worker.

       Handle all errors in the capture loop: if `readSamples` throws (e.g., device disconnected), catch the error, stop capture, and post error status.

    1. Create `src/lib/dsp/dsp-worker.ts` -- DSP Worker skeleton:
       ```typescript
       /// <reference lib="webworker" />
       ```

       The DSP Worker is a skeleton in Phase 1. It:
       - Receives `UsbToDspMessage` via its port (MessagePort from the bridge's MessageChannel)
       - On `'init'` message: receives SharedArrayBuffer, creates a RingBuffer reader from it using `getRingBufferReader(sab)`
       - On `'capture-started'`: starts a polling loop that reads from the ring buffer (e.g., every 10ms via setTimeout). In Phase 1 it simply discards the data but tracks how many samples it read. Posts `{ type: 'dsp-stats', samplesProcessed }` to main thread periodically (every 500ms).
       - On `'capture-stopped'`: stops the polling loop
       - Posts `{ type: 'dsp-ready' }` to main thread on initialization

       This is explicitly a skeleton -- Phase 2 will add FFT processing, Phase 3 will add demodulation. But the worker must exist and read from the ring buffer to prevent buffer overflow.

    2. Create `src/lib/workers/worker-bridge.ts` -- orchestrates worker lifecycle:

       ```typescript
       export interface WorkerBridge {
         connect(): void;
         disconnect(): void;
         configure(frequency: number, gain: number | null, sampleRate: number): void;
         startCapture(): void;
         stopCapture(): void;
         destroy(): void;
       }
       ```

       `createWorkerBridge()` function:
       - Creates USB Worker: `new Worker(new URL('../usb/usb-worker.ts', import.meta.url), { type: 'module' })`
       - Creates DSP Worker: `new Worker(new URL('../dsp/dsp-worker.ts', import.meta.url), { type: 'module' })`
       - Creates a MessageChannel. Sends one port to USB Worker (`{ type: 'set-dsp-port', port }` with transfer), one port to DSP Worker (via postMessage with transfer).
       - Listens for `UsbToMainMessage` on USB Worker's `onmessage`:
         - `'status'`: Update `sdrState.connectionStatus` and `sdrState.errorMessage`
         - `'device-info'`: Log to console (no UI for device info in Phase 1)
         - `'stats'`: Call `updateStats(msg.samplesReceived, msg.droppedSamples, msg.bufferFill)`
       - Listens for `DspToMainMessage` on DSP Worker's `onmessage`:
         - `'dsp-ready'`: Log "DSP Worker ready"
         - `'dsp-stats'`: Log to console (Phase 2+ will use this)
       - Returns a WorkerBridge object with methods that post typed messages to USB Worker:
         - `connect()` -> posts `{ type: 'connect' }`
         - `disconnect()` -> posts `{ type: 'disconnect' }`
         - `configure(f, g, sr)` -> posts `{ type: 'configure', frequency: f, gain: g, sampleRate: sr }`
         - `startCapture()` -> posts `{ type: 'start-capture' }`, sets `sdrState.capturing = true`
         - `stopCapture()` -> posts `{ type: 'stop-capture' }`, sets `sdrState.capturing = false`, calls `resetStats()`
         - `destroy()` -> terminates both workers
